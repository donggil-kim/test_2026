# 방법론 — 통합 클라우드 보안위협 매트릭스

## 1. 설계 원칙

통합 AI 보안위협 매트릭스 v3.2의 논리를 클라우드 보안에 이식한다.

| 구분 | AI 매트릭스 v3.2 | 본 클라우드 매트릭스 |
|---|---|---|
| Lv1 도메인 | 공격 생애주기·주제(D01~D10) | **ATT&CK 전술(킬체인)** 14개 |
| Lv2 위협분류 | UT-xx | ATT&CK 기법 (`CTC-<전술>-NN`) |
| Lv3 세부위협 | UT-xx.y | 하위기법/벤더 항목 (`CTC-<전술>-NN.M`) |
| 위험평가 | 발생가능성×심각도→위험도 | 동일 |
| 근거수준 | ATLAS 사례/실제사고 기반 4등급 | ATT&CK 사례/사고DB 기반 4등급 |

도메인 뼈대로 ATT&CK 킬체인을 선택한 이유: 공격 단계가 명확히 서열화되고, 기존 Cloud
ATT&CK 통합본·벤더 매트릭스와 ID 수준에서 직접 연결되어 매핑 신뢰도가 높다.

## 2. 입력 데이터

1. **Cloud ATT&CK 통합본** (`data/Cloud_ATTACK_Matrix_Integrated_v19.2.xlsx`)
   ATT&CK Cloud v19.2(전술 14·기법 87·하위기법 93) + AWS TTC + Azure ATRM + K8s,
   기법별 클라우드 실제 사례 수 포함.
2. **클라우드 보안사고 DB** (`data/Cloud_IncidentDB_v2_LITE.xlsx`)
   680건(2010~2026). 사례유형·근본원인·영향·서비스계층·ATT&CK 초안 ID 분류.
3. **CSA Top Threats 2026 / CCM v4.1** — 연계(ID) 참조만. 원문 미수록.

## 3. 분류체계 조립 규칙

- 전술 행 → Lv1 도메인 메타.
- 하위기법을 가진 기법 → **Lv2 그룹**. 그 하위기법들이 Lv3 리프이며, 상위기법 자체에 근거(사고 태그·ATT&CK 사례·벤더 항목)가 있으면 `.0 (일반·상위기법)` 리프로 보존한다.
- 하위기법이 없는 기법 → 자신이 Lv2이자 Lv3 리프.
- 벤더 전용(ATT&CK 미대응, 예: Azure Soft-Delete Recovery) → 해당 전술 아래 Lv3 리프.
- 한 기법이 여러 전술에 속하면 전술마다 반복 표시(ATT&CK 원칙과 동일).

## 4. 교차 매핑

- **AWS/Azure/K8s** — 통합본의 벤더 열(`• ID 이름 …`)을 그대로 Lv3에 연결.
- **CSA Top Threats 2026** — ATT&CK 기법 ID → 11대 위협 번호 매핑
  (`scripts/taxonomy_rules.py`의 `CSA_MAP`, 하위기법 키가 있으면 상위기법 매핑을 대체). 예: T1190 → SI-04(인터페이스·API),
  SI-11(시스템 취약점). SI-02(AI를 이용한 공격)·SI-08(거버넌스)은 기법 비종속·비기술 위협이라 개별 행에 매핑하지 않고,
  `CSA 2026 연계` 시트의 '연계 기준' 열(`CSA_NOTE`)에 사유를 적는다.
- **SI-06(AI 시스템 침해) 재검토 (v5)** — v4까지 T1496 자원 악용 전체(하위기법 4개 + `.0` 행)를 SI-06에 연계해,
  사고 DB 크립토재킹 사고 127건이 모두 'AI 시스템 침해'로 집계됐다. SI-06은 모델·프롬프트·학습/추론 데이터·연결 도구 등
  AI 시스템 자체의 침해를 다루는데, T1496 사고의 근본원인은 취약점 악용·오설정/노출 서비스·자격증명 계열이고 기법 정의에서
  AI 자원을 다루는 것은 T1496.004(관리형 LLM 무단 호출, LLMjacking)뿐이다. 그래서 다음처럼 바꿨다.

  | 대상 | v4 | v5 | 근거 |
  |---|---|---|---|
  | T1496 상위·.001·.002 | SI-06 | 미연계 | 영향 기법은 다른 영향 기법(T1485·T1486·T1490 등)처럼 CSA 이슈 미연계. 침투 경로를 기법 단위로 붙이면 SI-01·05·11의 사고 수가 사고마다의 실제 원인과 무관하게 100건 이상씩 부풀려짐 |
  | T1496.003 SMS 펌핑 | SI-06 | SI-04 | 레이트 제한 없는 공개 폼·API의 자원 고갈(CSA SI-04 영향 항목) |
  | T1496.004 클라우드 서비스 악용 | SI-06 | SI-01 · SI-06 | 탈취 키로 관리형 AI 자원 악용(LLMjacking) — SI-06을 유지하는 유일한 행 |

  AI 시스템 자체 위협(프롬프트 주입·모델/데이터 오염·에이전트 악용)은 클라우드 ATT&CK 기법으로 표현되지 않으므로
  통합 AI 매트릭스 v3.2(UT)에서 다룬다. CSA 보고서의 SI-06 사례 중 Salesloft Drift 통합 침해는 신뢰 관계·앱 토큰 기법
  (T1199·T1671)의 참조 문구에 출처로만 인용한다.

## 5. 근거 집계

AI 매트릭스의 'ATLAS 사례 수'·'실제 사고 수'에 대응하도록 신호를 분리 집계한다.

- **실제 사고 수** — 사고 DB 중 사고·캠페인·사례연구·공시·위협인텔 유형, ATT&CK 초안 ID + 키워드 매핑 기준.
  폐기 ID는 v19.2로 변환(T1562→T1685 등). 하위기법으로 세분되지 않은 상위기법 태그는 `.0` 행에 집계.
- **최근 사고(2025~)** — 위 중 기준일 2025년 이후.
- **실증·연구 수** — 사고 DB의 '연구·노출' 유형.
- **ATT&CK 사례 수** — 통합본의 기법별 클라우드 procedure 사례 수.
- 집계 제외: 클라우드 관련도 '비클라우드 의심'. 매핑되지 않은 사고도 `역매핑_사고사례`에 전수 보존.

### 사고 → 기법 키워드 매핑 (v5)

v4까지는 사고 DB의 ATT&CK 초안 ID만 썼다. 초안 ID가 있는 사고는 집계 대상 655건 중 245건뿐이었고, 그마저 상위기법
태그(크립토재킹 T1496 127건, 피싱 T1566 등)가 많아 하위기법 행에는 근거가 비어 있었다. v5는 초안 ID에 키워드 규칙을 더한다.

- **규칙** — `scripts/taxonomy_rules.py`의 `KEYWORD_RULES`(62개). 각 규칙은 (기법, 키워드 정규식, 조건)이며, 키워드는 사고 제목·요약·원문
  필드(초기침투·확산·영향·사용 기법·공격 대상·도구)에서 찾는다. 조건은 DB의 구조 필드로 정밀도를 높인다.
  예: T1190은 근본원인 '취약점 악용' + 서비스 계층 '노출 워크로드/엣지 장비' + CVE·RCE·익스플로잇 키워드(공급망 사고 제외),
  T1195.002는 근본원인 '공급망·서드파티' + 계층 '패키지·공급망' + 패키지·의존성·빌드 키워드.
- **세분** — 초안에 상위기법만 있고 키워드가 하위기법을 가리키면 상위 태그를 하위기법으로 옮긴다(근거 `초안ID→키워드 세분`).
  하위기법 규칙을 상위기법 규칙보다 먼저 적용하고, 같은 기법·하위기법이 이미 있으면 추가하지 않는다.
- **근거 표시** — 통합 매트릭스의 '사고 매핑 근거' 열과 `역매핑_사고사례`의 '매핑 기법(근거)' 열에 `초안ID`·`키워드`·`초안ID→키워드 세분`을
  구분해 남겨, 키워드로 붙은 연결만 골라 검토할 수 있다.
- **정밀도 관리** — 규칙별 일치 사고를 전수 검토해 오탐 패턴을 제외 조건(`neg`)으로 막았다. 예: 회사명 Twilio·Dropbox, 데이터 탈취형
  갈취를 '랜섬웨어'로 부른 사례(T1486 제외), 피해 서버를 DDoS 봇넷에 동원한 사례(서비스 거부 T1499 대신 대역폭 악용 T1496.002로 연결),
  패키지 typosquatting(도메인 확보 T1583.001에서 제외), 사고 요약의 부정문("DB는 영향 없음")을 피하도록 키워드와 행위 동사의 근접 조건 적용.

| 구분 | v5 (2/3) | v5 (3/3) |
|---|---|---|
| 기법 매핑된 사고(집계 대상 655건 중) | 245건 | 452건(키워드로만 매핑 207건) |
| 사고-기법 연결 | 초안ID 289 | 초안ID 167 · 키워드 488 · 초안ID→키워드 세분 132 |
| 실제 사고가 있는 고유 기법 | 20개 | 59개 |
| T1496 자원 악용 | `.0` 127건 | `.0` 15 · 컴퓨트(.001) 108 · 대역폭(.002) 9 · 서비스(.004) 27 |

발생가능성은 §6 수식을 그대로 적용하므로 근거가 늘어난 43개 행의 발생가능성·위험도가 바뀌었다(위험도 분포 매우 높음 16→40 ·
높음 60→53 · 보통 60→45 · 낮음 18→16). 하향은 저장소별 하위 행으로 사고가 모두 옮겨 간 T1213 `.0` 행 하나다.

## 6. 평가 로직

### 발생가능성 (근거 자동 산정, AI 매트릭스 v3.2 수식과 동일 — v5)
- 상: 실제 사고 ≥2건
- 중: 실제 사고 1건, 또는 ATT&CK 클라우드 사례·실증 연구·벤더 특화기법 중 하나 이상
- 하: 근거 없음(이론·시나리오)

AI 매트릭스 v3.2의 수식 `G = IF(실제사고>=2,"상", IF(OR(실제사고=1, ATLAS사례>0, Realized>0, 취약점>0),"중","하"))`을
다음 대응 관계로 그대로 적용한다.

| AI 매트릭스 v3.2 근거 | 본 매트릭스 근거 | 반영 상한 |
|---|---|---|
| 실제 사고(ATLAS Incident + OWASP 인용) | 사고 DB 실제 사고(사고·캠페인·사례연구·공시·위협인텔) | 상(2건 이상) |
| Realized 기법(실사용) | ATT&CK 클라우드 사례(그룹·캠페인·악성코드) | 중 |
| 실증 사례·공개 취약점 | 사고 DB 연구·노출 + 벤더 매트릭스(AWS TTC·Azure ATRM·K8s) 문서화 | 중 |

v4까지는 '상 = 실제 사고 ≥3건 또는 ATT&CK 사례 ≥10건'으로 AI 매트릭스와 기준값이 달랐다(이전 빌드가 수식이 값으로
변환된 LITE본만 참조). v5에서 통일하면서 11개 행(고유 기법 8개)의 발생가능성·위험도가 바뀌었다 — 실제 사고 2건인
T1556.006·T1557·T1606.002는 상향, 실제 사고 없이 ATT&CK 사례만 10건 이상인 T1566.002·T1555.006·T1580·T1550.001·T1213.003은 하향.

### 심각도 (기법별 기준값, `scripts/taxonomy_rules.py`)
- 상: 데이터 파괴·암호화·중단, 자원·과금 손실, 대량 유출, 자격증명·토큰·키 탈취, 권한·신뢰 변경, 외부 진입 경로
- 하: 열람·탐색 위주
- 그 외: 전술 기준값

### 위험도 (발생가능성 × 심각도)
| | 심각도 상 | 중 | 하 |
|---|---|---|---|
| 발생 상 | 매우 높음 | 높음 | 보통 |
| 발생 중 | 높음 | 보통 | 낮음 |
| 발생 하 | 보통 | 낮음 | 낮음 |

### 근거 수준 (높은 순)
`실제 사고 확인` → `실사용 기법 포함` → `실증·공개 취약점` → `이론·시나리오`

## 7. 클라우드 특화 검토 (v3)

판정 기준: 클라우드 전용은 유지 / 혼합은 클라우드 맥락(IaaS·SaaS·IdP·M365/Office Suite)이 있으면 유지 /
클라우드 외 연관은 K8s·컨테이너·클라우드 사고 맥락이 있을 때만 유지. 판정표는 `scripts/taxonomy_rules.py`의 `DROP`·`MERGE`.

- **삭제(11)**: T1189, T1211, T1687, T1212, T1040, T1201, T1680, T1048, 연결용 상위기법 T1036·T1686·T1020
- **통합(31)**: 상위기법 '(일반)' 행 → 클라우드 하위기법(T1078→T1078.004 등), 일반 탐색 → T1580·T1526,
  서비스 거부 하위기법 → T1499, 클라우드 외 연관 일부 → 관련 클라우드 기법(T1583→T1583.001 등)
- 통합 시 사고·ATT&CK 사례·벤더 항목은 대상 행에 합산하고 '통합된 기법' 열과 참조에 원 기법을 남긴다.

## 8. 설명 열 구성 (v4 — 클라우드 특화 재작성)

v4부터 설명을 기존 번역문 그대로 두지 않고, ATT&CK 원문·벤더 매트릭스(AWS TTC·Azure ATRM·K8s)·사고 DB·CSA Top Threats 2026을 함께 분석해 클라우드 관점으로 재작성한다. 작성 기준:

- **요약설명**: 2줄 개조식, 명사형 종결(AI 매트릭스 v3.2 Lv3 설명 형식과 통일).
  - 1줄 — 위협 메커니즘(공격자는 어떤 클라우드 대상을 어떤 수단으로 악용해 무엇을 하는가).
  - 2줄 — 클라우드 발생 조건·영향 범위·탐지 곤란 사유 중 핵심.
  - 일반 엔터프라이즈 용어(호스트·도메인 컨트롤러 등) 대신 클라우드 용어(IAM·테넌트·제어 평면·관리형 서비스)를 쓴다.
- **참조**: 두 절로 구성.
  - `■ 클라우드 관점` — 대상 서비스·API, 전제 조건, 변형, 벤더 기법 ID(AWS AT…·Azure AZT…·K8s MS-TA…), 통합 범위.
  - `■ 실제 사례` — 사고 DB(해당 행에 매핑된 사고만)·ATT&CK 사례·CSA 2026 사례 최대 3건, 출처 표기(INC-/G·S·C/SI-). 공개 사고가 없으면 근거 상태를 명시한다.
- **탐지·대응 포인트**(신설 열): `■ 탐지`(로그·행위 단서)와 `■ 대응`(통제·설정)을 세부위협별로 제시한다.
- **사용자 문구**: `data/threat_text_override.csv`에 세부위협명·요약설명·참조·탐지대응을 입력하면 해당 기법의 기본값을 대체한다('설명 출처' 열). 미작성 기법은 기존 번역 설명(§8의 v3 기본값)을 유지한다.

분류체계·교차매핑·위험평가·근거 집계 로직은 v3와 동일하며, v4에서 바뀐 산출물 열은 요약설명·참조·설명 출처와 신설된 탐지·대응 포인트뿐이다.

## 9. 한계

- 클라우드 관점 재작성은 고유 기법 126개 전체(세부위협 154행)에 적용 완료했다. 요약설명·참조·탐지대응을 모두 override로 작성했으며 '설명 출처'는 전 행이 '사용자 입력'이다.
- 재작성 문구의 사례·수치는 입력 데이터(ATT&CK 원문·사례, 사고 DB, 벤더 원본)와 CSA 2026 본문 범위에서만 인용하며, 탐지·대응 포인트는 일반적 권고 수준으로 조직 환경에 맞춘 검증이 필요하다.
- 사고→기법 매핑은 초안 ID에 키워드 규칙(v5)을 더한 것이다. 규칙별 일치 사고를 검토해 오탐을 줄였지만, 키워드 매핑은 사고 요약문에
  의존하므로 요약이 짧거나 잘린 사고는 빠지고 일부 오연결이 남을 수 있다. '사고 매핑 근거'가 `키워드`인 연결은 운영 전 표본 검토를 권장한다.
- 위험평가 값은 기준값이며 조직 맥락(데이터 민감도·노출 범위)에 따라 조정이 필요하다.
- CSA 연계는 기법 주제 기반 1차 매핑으로, 운영 전 검토를 권장한다. 사고별 근본원인에 따른 CSA 연계(사고 단위)는 적용하지 않았다.
