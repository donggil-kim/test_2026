# 방법론 — 통합 클라우드 보안위협 매트릭스

## 1. 설계 원칙

통합 AI 보안위협 매트릭스 v3.2의 논리를 클라우드 보안에 이식한다.

| 구분 | AI 매트릭스 v3.2 | 본 클라우드 매트릭스 |
|---|---|---|
| Lv1 도메인 | 공격 생애주기·주제(D01~D10) | **ATT&CK 전술(킬체인)** 14개 |
| Lv2 위협분류 | UT-xx | ATT&CK 기법 (`CTC-<전술>-NN`) |
| Lv3 세부위협 | UT-xx.y | 하위기법/벤더 항목 (`CTC-<전술>-NN.M`) |
| 위험평가 | 발생가능성×심각도→위험도 | 동일 |
| 근거수준 | ATLAS 사례/실제사고 기반 4등급 | ATT&CK 사례/사고DB 기반 4등급 |

도메인 뼈대로 ATT&CK 킬체인을 선택한 이유: 공격 단계가 명확히 서열화되고, 기존 Cloud
ATT&CK 통합본·벤더 매트릭스와 ID 수준에서 직접 연결되어 매핑 신뢰도가 높다.

## 2. 입력 데이터

1. **Cloud ATT&CK 통합본** (`data/Cloud_ATTACK_Matrix_Integrated_v19.2.xlsx`)
   ATT&CK Cloud v19.2(전술 14·기법 87·하위기법 93) + AWS TTC + Azure ATRM + K8s,
   기법별 클라우드 실제 사례 수 포함.
2. **클라우드 보안사고 DB** (`data/Cloud_IncidentDB_v2_LITE.xlsx`)
   680건(2010~2026). 사례유형·근본원인·영향·서비스계층·ATT&CK 초안 ID 분류.
3. **CSA Top Threats 2026 / CCM v4.1** — 연계(ID) 참조만. 원문 미수록.

## 3. 분류체계 조립 규칙

- 전술 행 → Lv1 도메인 메타.
- 하위기법을 가진 기법 → **Lv2 그룹**. 그 하위기법들이 Lv3 리프이며, 상위기법 자체에 근거(사고 태그·ATT&CK 사례·벤더 항목)가 있으면 `.0 (일반·상위기법)` 리프로 보존한다.
- 하위기법이 없는 기법 → 자신이 Lv2이자 Lv3 리프.
- 벤더 전용(ATT&CK 미대응, 예: Azure Soft-Delete Recovery) → 해당 전술 아래 Lv3 리프.
- 한 기법이 여러 전술에 속하면 전술마다 반복 표시(ATT&CK 원칙과 동일).

## 4. 교차 매핑

- **AWS/Azure/K8s** — 통합본의 벤더 열(`• ID 이름 …`)을 그대로 Lv3에 연결.
- **CSA Top Threats 2026** — 상위 ATT&CK 기법 ID → 11대 위협 번호 매핑
  (`scripts/build_cloud_threat_matrix.py`의 `CSA_MAP`). 예: T1190 → SI-04(인터페이스·API),
  SI-11(시스템 취약점). SI-02(AI 공격)·SI-08(거버넌스)은 교차·비기술 성격이라 개별 행 대신
  개요 수준에서 다룬다.

## 5. 근거 집계

AI 매트릭스의 'ATLAS 사례 수'·'실제 사고 수'에 대응하도록 신호를 분리 집계한다.

- **실제 사고 수** — 사고 DB 중 사고·캠페인·사례연구·공시·위협인텔 유형, ATT&CK 초안 ID 기준.
  폐기 ID는 v19.2로 변환(T1562→T1685 등). 상위기법 ID만 붙은 사고는 `.0` 행에 집계.
- **최근 사고(2025~)** — 위 중 기준일 2025년 이후.
- **실증·연구 수** — 사고 DB의 '연구·노출' 유형.
- **ATT&CK 사례 수** — 통합본의 기법별 클라우드 procedure 사례 수.
- 집계 제외: 클라우드 관련도 '비클라우드 의심'. 초안 ID 없는 사고는 `역매핑_사고사례`에 전수 보존.

## 6. 평가 로직

### 발생가능성 (근거 자동 산정, AI 매트릭스 v3.2와 동일 원칙)
- 상: 실제 사고 ≥3건 또는 ATT&CK 사례 ≥10건
- 중: 실제 사고 1~2건, 또는 ATT&CK 사례·실증 연구·벤더 특화기법 중 하나 이상
- 하: 근거 없음(이론·시나리오)

### 심각도 (기법별 기준값, `scripts/taxonomy_rules.py`)
- 상: 데이터 파괴·암호화·중단, 자원·과금 손실, 대량 유출, 자격증명·토큰·키 탈취, 권한·신뢰 변경, 외부 진입 경로
- 하: 열람·탐색 위주
- 그 외: 전술 기준값

### 위험도 (발생가능성 × 심각도)
| | 심각도 상 | 중 | 하 |
|---|---|---|---|
| 발생 상 | 매우 높음 | 높음 | 보통 |
| 발생 중 | 높음 | 보통 | 낮음 |
| 발생 하 | 보통 | 낮음 | 낮음 |

### 근거 수준 (높은 순)
`실제 사고 확인` → `실사용 기법 포함` → `실증·공개 취약점` → `이론·시나리오`

## 7. 한계

- 사고→기법 매핑은 DB의 초안 ID 기준이라 보수적이다(키워드 확장 미적용). 초안 ID가 있는 사고는 680건 중 254건이며, 상위기법 ID만 붙은 사고(예: 크립토재킹 T1496)는 하위기법으로 세분되지 않고 `.0` 행에 모인다.
- 위험평가 값은 기준값이며 조직 맥락(데이터 민감도·노출 범위)에 따라 조정이 필요하다.
- CSA 연계는 기법 주제 기반 1차 매핑으로, 운영 전 검토를 권장한다.
