**CISA KEV — 판정 방법(공급망 KEV 판정과 같은 방식)**

- 집계해 보면 CWE만으로는 부족하고 키워드만으로는 너무 넓습니다.
  - 인증 계열 CWE(287·288·290·294·306·798·522·347·1390 등)로 고르면 **142건**(2021~2026 등재: 21·17·16·22·24·42 — 최근 급증).
  - 키워드(authentication·credential·session·token·SSO 등)로 고르면 706건으로 과다합니다(일반 권한 상승 취약점이 섞임).
  - 핵심 신원 취약점이 인증 CWE로 분류되지 않은 경우가 많습니다. 예: Zerologon CVE-2020-1472(CWE-330), Citrix Bleed CVE-2023-4966(CWE-119)·
    CVE-2025-5777(CWE-125), noPac CVE-2021-42278/42287(CWE-20·269), AD CS CVE-2022-26923(CWE-295).
- 그래서 **① 인증 계열 CWE 후보 + ② 신원·접근 인프라 제품(AD·Netlogon·Kerberos·IdP·SSO·VPN·원격접속 게이트웨이 등) 후보 → ③ 수동 판정**으로
  분류합니다. 판정 분류 초안은 다음과 같습니다.
  - 인증 우회
  - 세션·토큰 탈취/재사용(메모리 노출 포함)
  - 하드코딩·기본 자격증명
  - 디렉터리·Kerberos 권한 상승
  - 서명·인증서 검증 결함
  - IdP·SSO·페더레이션 제품
  - 원격접속 게이트웨이 인증
- '디렉터리·Kerberos 권한 상승'처럼 신원 체계를 직접 장악하는 취약점만 넣고, 일반 OS 권한 상승은 제외합니다(판정 사유 열 기록).
- 공급망 판정(80건)과 겹치는 CVE는 양쪽에 두되, 매트릭스 간 비교는 하지 않습니다(4장).

**Browser & Identity Attacks Matrix — 활용 방법**

- 51개 기법 중 ATT&CK 링크가 붙은 것은 21개뿐입니다. 신원 매트릭스의 SAT-ID 매핑이 ATT&CK에 없는 기법을 보완하는 역할을 합니다.
  - 해당 기법: SAMLjacking, Poisoned tenants, Ghost logins, Cross-IdP impersonation, nOAuth, ConsentFix, MFA downgrade, Account ambushing, Evil twin integrations, Shadow workflows 등
- 분류 체계 반영 후보(7장 도메인 기준):
  - SE: Consent·Device code·Verification·App-specific password phishing, Hijack OAuth flows, ConsentFix, UI redressing
  - AU: MFA downgrade, Credential stuffing, App spraying, Username enumeration
  - TS: Session cookie theft
  - DI: Inbound federation, Cross-IdP impersonation, SAMLjacking, nOAuth, Poisoned tenants
  - PE: Ghost logins, Device enrollment, Malicious mail rules, Link backdooring
  - NH: OAuth tokens, API keys, Evil twin·System integrations, Abuse existing OAuth integrations
  - LC: Guest access abuse, Account ambushing, Link sharing
  - IM: Takeout services, Webhooks, Shadow workflows
- 범위 차이: 이 매트릭스는 엔드포인트를 거치지 않는 공격만 다룹니다. AD·Kerberos·OS 자격증명 덤프·인포스틸러는 ATT&CK과 사고 DB로 채웁니다.
- 갱신이 잦은 자료이므로 커밋 해시를 기준선으로 고정하고 `reference/push-bia/`에 ID·명칭·전술·참고 링크 추출본(`prepare_push.py`)만 둡니다.
- 문구에는 `[실증]` 또는 `참고:`로만 인용합니다(`[실제 사고]` 라벨 금지 — 검증기 규칙 추가).

## 6. 평가 기준 (신원 결과 기준 심각도 — 초안)

- **상**: 성공하면 IdP·디렉터리·토큰 서명 키·특권 계정을 장악해 **조직(테넌트) 전체 또는 다수 계정에 임의 인증·토큰 위조**가 가능하거나,
  인증 통제(MFA 등)를 체계적으로 우회해 대규모 계정 탈취·금전 피해·랜섬웨어로 이어지는 위협
- **중**: 단일 사용자·계정 범위에 머물거나 사용자의 선택·실수가 필요한 위협, 또는 단독 피해는 없고 다른 위협을 키우는 조건(과다 권한·휴면 계정 등)
- **하**: 영향이 제한적·일시적이고 복구가 쉬운 위협(예: 단순 계정 잠금 유발)
- 발생가능성·위험도·근거 수준·우선순위는 기존 매트릭스와 동일. 위험도 포화(공급망 60개 중 38개 '매우 높음')를 피하려면
  '상' 판정 시 **'장악 범위(조직 전체/다수 계정)'**를 반드시 확인 — 0단계에서 행별 심각도 근거 열에 기록.
