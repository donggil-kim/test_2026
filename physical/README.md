# 물리·인적 보안위협 매트릭스

드론 무단촬영·물리 침입·인적 포섭·위장취업·내부자 정보유출처럼 **물리적·실세계 공격** 관점의 보안위협을 하나의 매트릭스로 정리했습니다.
앞서 만든 통합 AI v3.2, 클라우드 v5, OT v5, 소프트웨어 공급망 v2, 아이덴티티 v2 매트릭스의 구조와 산정 로직을 물리·인적 영역에 이식했습니다.
구조는 분류 → 위험평가 → 실제근거 → 대응 기준 → 관점 문구 순서입니다.

- **분류**: 물리·인적 공격면 7개 도메인 → 위협분류 31개 → 세부위협 45개(`data/taxonomy.yaml`). 한 행은 한 행위이고, 공격 단계·위협 주체 유형·적용 프로파일은 열로 병기합니다.
- **교차 매핑**: MITRE ATT&CK v19.2(물리·인적 접점 기법 24개, 16개 행) · MITRE CTID 내부자 TTP 지식베이스(ITKB, 관측 기법 70개 중 8개 행 표시)
- **실제 근거**: 물리·인적 보안사고 DB 100건(2009~2026, 공개 출처, 국내 25건). 정부 경보·위협인텔·연구 실증은 '중' 상한으로만 반영합니다.
- **대응 기준**: NIST SP 800-53 Rev.5 · ISO/IEC 27001:2022 부속서 A 5~7 · ISMS-P 2.2~2.4(+관련 항목) · CERT 내부자 가이드 7판 실천과제
- **참고 문헌**: NPSA 지침 8종 · CISA 지침 2종 · ISO 22341 — 분류 근거·위협 내용·대응 문구의 인용 자료(발생가능성 산정에는 넣지 않음)
- **물리 관점 문구(v2)**: 45개 전부 작성(7개 도메인, 인용 사례 174건). 검증기로 사고 DB와 대조해 오류·경고 0건입니다.
- **공격 체인 시나리오(v2)**: 사고 30건(국내 12건)을 물리·인적 공격 흐름 8개로 재구성하고, 단계마다 세부위협·탐지 포인트, 흐름마다 초크 포인트를 표시했습니다.
- **다른 매트릭스 연계**: 아이덴티티 v2(IDT-) · 공급망 v2(SCT-) · OT v5(OTC-) · 통합 AI·클라우드·OT v2(AI-·CL-·OT-). 계정·디지털 경로는 원 매트릭스 ID로 넘깁니다.

> **방어 자료입니다.** 행과 문구는 위험 자산·탐지 지점·통제 중심으로 서술하고, 침입·도청·촬영·포섭의 실행 방법은 다루지 않습니다.
> 인적 지표는 객관적 행동·직무 사실만 쓰고(보호 특성 제외), 드론 무력화·전파 교란은 권고하지 않습니다(탐지·식별·신고·차폐).

> 위치: 다른 매트릭스와 같이 이 저장소의 `physical/` 폴더에 두었습니다. 모든 경로가 이 폴더 기준입니다.
> 연계 ID 갱신(`scripts/prepare_refs.py`)에는 같은 저장소의 `identity/`·`supplychain/`·`ot/`·`integrated/`가 필요합니다.

## 결과 요약(v2)

- **위험도**: 매우 높음 15 · 높음 23 · 보통 6 · 낮음 1
- **근거 수준**: 실제 사고 확인 43 · 실사용 기법 포함 1(PA-05 배송·설치·정비 과정) · 실증·공개 취약점 1(SV-03.2 부채널)
- **심각도**: 상 17 · 중 27 · 하 1. '상'은 핵심기술 통째 유출·기반시설 운영·안전·장기 잠복 내부 접근일 때만 줍니다. 공급망의 위험도 포화(60개 중 38개 매우 높음)를 피하려는 기준입니다.
- **우선 위협(단계 위협 기준)**: 결과 유형인 IM 도메인을 뺀 상위 순서입니다.
  1. 재직자의 기밀·기술 자료 무단 수집·유출(IN-02.1, 실제 사고 13건)
  2. 퇴직·이직 직전 자료 대량 반출(IN-03.1, 8건)
  3. 이동식 저장매체·업무 단말 무단 반출(EX-01, 8건)
  4. 브로커·위장 법인을 통한 핵심 인력 영입(HU-02, 7건)
  5. 금전 제공으로 재직자 포섭·매수(HU-01.1, 7건)
  6. 이직·창업 후 전 직장 기술 재현·사용(IN-03.2, 5건)
  7. 합작·위탁생산·거래 상담을 가장한 기술 자료 요구(HU-05.2, 4건)
  8. 도용·위조 신분으로 원격 개발직 위장취업(IN-01.1, 3건)
- **국내 사고가 몰린 위협**: 퇴직 직전 반출(IN-03.1, 5건) · 재직자 유출(IN-02.1) · 인력 영입(HU-02) · 이직 후 재현(IN-03.2) · 협력사 인력 반출(IN-04, 각 4건)
- **최근(2025~) 사고가 몰린 위협**: 인력 영입(HU-02) · 드론 무단 비행·반복 출현(SV-01.2, 각 3건) · 협력사 인력 반출(IN-04) · 현장 답사(RC-02) · 근접 무선 가로채기(SV-03.1, 각 2건)
- **한계**: 공개 사고 기준이라 기소·판결로 드러나는 기술 유출·내부자 사건이 높게 나오고, 공개·귀속되지 않는 물리 침입·은닉 감시는 과소평가될 수 있습니다.
  드론은 공항 운영 방해·군사시설 촬영 사례는 많지만 기업 기술 스파이로 귀속된 공개 사례는 확인하지 못했습니다(`docs/METHODOLOGY.md` §12).

## 물리 관점 문구(`data/text/<도메인>.yaml`)

```yaml
PHT-IN-03.1:
  oneline: 퇴직·이직 직전 출력·촬영·저장장치로 공정·설계 자료를 대량 반출   # 50자 이내 명사형
  summary: |-                                                             # 2줄 개조식
    - 악의적 내부자는 … 수 있음
    - … 피해 특성 또는 탐지가 어려운 이유
  reference: |-
    ■ 물리 관점
    - 대상: … / 징후(식별 수준): … / 통제 원칙: … / 연계: …(PHT-ID, 다른 매트릭스 ID)
    - 참고: NPSA 〈내부자 위험 완화 프레임워크〉
    ■ 실제 사례
    - [실제 사고] 퇴사 전 공정 문서 출력·태블릿 촬영(2024-05): … (PHI-025)
  detect: |-
    ■ 탐지
    - …(NIST AU-13, CERT 14)
    ■ 대응
    - …(NIST PS-4, ISO 27001 5.11·6.5, ISMS-P 2.2.5, CERT 20)
    - 참고: NPSA 〈내부자 위험 완화 프레임워크〉
```

- **인용 범위**
  - 사례는 그 행에 매핑된 사고만 인용하고, 수치·경위는 사고 DB 요약에 있는 것만 씁니다. 개인은 실명 대신 직책·관계로 적습니다.
  - 라벨은 `[실제 사고]`·`[정부 경보]`·`[위협인텔]`·`[실증]`입니다. 공개 사례가 없으면 `공개 사고 미확인 — 사유`로 씁니다.
  - 참고 문헌은 `■ 물리 관점`·`■ 대응` 끝의 `참고: NPSA 〈…〉` 줄로만 인용합니다(요지 의역, 원문 비수록).
- **작성 수준**: 방어 측 보고서용입니다. 수법은 탐지·식별에 필요한 '징후' 수준까지만 적고, 대응은 예방 → 차단 → 탐지 순의 합법적 조치만 씁니다.
  - 드론 행은 탐지·식별·신고·차폐만 권고합니다. 임직원 모니터링은 개인정보보호법·노사 협의 범위 안에서만 권고합니다.
  - IM(영향·피해) 행은 결과 유형이라 '■ 물리 관점'에 그 결과로 이어지는 앞 단계 세부위협(PHT-ID)을 적었습니다.
  - 사고가 많이 매핑된 행(예: IM-01 23건)은 최근·국내·대형 사고 중심으로 대표 사례만 골랐습니다. 전체 목록은 '역매핑_사고사례' 시트에 있습니다.
- **현황**: 45개 전부 작성(RC 4 · PA 7 · SV 8 · HU 8 · IN 9 · EX 4 · IM 5).
  - 인용 사례 174건: [실제 사고] 164 · [정부 경보] 7 · [실증] 2 · [위협인텔] 1
  - 실제 사고가 없는 PA-05·SV-03.2는 '공개 사고 미확인 — 사유'를 함께 적었습니다.
- **검증**: 문구를 고치면 `python3 scripts/validate.py`로 대조합니다. 빌드 때도 자동 실행됩니다. 규칙 전체는 `docs/METHODOLOGY.md` §9~10에 있습니다.

## 공격 체인 시나리오(`data/scenarios.yaml`)

흐름을 가장 싸게 끊는 통제를 초크 포인트로 표시했습니다. 여러 사고를 이은 흐름은 단계마다 근거 사고를 괄호로 밝혔습니다.

## 재생성

```bash
pip install openpyxl pyyaml
python3 scripts/validate.py                              # 데이터·문구·시나리오 검증(--strict는 경고도 실패로 처리)
python3 scripts/build_physical_threat_matrix.py          # 검증 후 output/ 에 v2 워크북·CSV 생성

# (선택) v1 재현: 문구·시나리오 없이 분류·근거·평가만
python3 scripts/build_physical_threat_matrix.py --data-only --version v1
# (선택) 문구 작성용 근거 정리본(도메인별 .md — 행별 매핑 사고·ATT&CK 주체·대응 기준·참고 문헌)
python3 scripts/build_physical_threat_matrix.py --worksheet <폴더>
# (참고) --allow-missing-text: 문구를 새로 쓰는 중에 미작성 행을 오류 대신 목록으로만 두고 검증·빌드(중간 산출물용)
# (선택) 참조 자료 재생성
python3 scripts/prepare_attack.py                        # 저장소 루트 enterprise-attack-v19.2.xlsx → reference/attack/
git clone https://github.com/center-for-threat-informed-defense/insider-threat-ttp-kb.git <클론 경로>
python3 scripts/prepare_itkb.py --repo <클론 경로>        # → reference/itkb/
python3 scripts/prepare_refs.py                          # NIST 통제명 + 다른 매트릭스 연계 ID
```
