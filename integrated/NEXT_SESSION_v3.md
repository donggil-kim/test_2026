## 0. 먼저 지켜야 할 것(가드레일)

- **방어 자료 수준 유지**: 요약 문안은 원본 상세 매트릭스의 '요약설명'·'참조'·'탐지·대응 포인트'를 **요약**하는 작업입니다.
  - 원본보다 자세한 기법 설명을 새로 쓰지 않습니다. 단계별 실행 절차·도구 사용법·우회 요령은 쓰지 않습니다.
  - **위협 설명**: 무엇을 노리고 어떤 피해가 나는지.
  - **시나리오**: 원본 사례 경위 수준의 흐름.
  - **대응 방안**: 예방 → 차단 → 탐지 순.
- **물리·인적**: 원본 방법론 §1·§9 규칙을 그대로 적용하고, 검증기가 일부를 검사합니다(결정 D9).
  - 수법은 '징후' 수준까지만 씁니다.
  - 드론은 탐지·식별·신고·차폐만 권고합니다.
  - 인적 징후는 객관적 행동·직무 사실만 쓰고, 보호 특성은 쓰지 않습니다.
  - 개인은 실명 대신 직책·관계로 적습니다.
  - 임직원 모니터링은 개인정보보호법·노사 협의 범위로 한정합니다.
- **새 사실 금지**: 수치·사례·제품명은 구성 원본의 참조·요약설명·사고 DB 요약에 있는 것만 씁니다.
  - 대표 사례는 검증기가 원본 참조 줄과 글자 단위로 대조합니다.
- **저장소 아티팩트에 모델 식별자를 넣지 않습니다.** 커밋 메시지 귀속 라인은 현재 세션의 시스템 안내 문구를 씁니다.
- **PR은 사용자가 명시적으로 요청할 때만** 만듭니다.

## 2. 남은 작업 (순서대로, 도메인 단위 커밋 권장)

### 2.1 신원 문안 31개 — `integrated/data/identity/<도메인>.yaml`

도메인 순서: SE → CR → TS → DI → PE → NH → LC → CI → IM. 도메인마다 아래를 반복합니다.

1. **골격 생성**: `python3 integrated/scripts/v3_status.py --skeleton identity SE`
   - 재구성안의 id·name·members·basis가 채워지고, 대표 사례 후보는 주석으로 들어갑니다.
2. **원본 확인**: `python3 integrated/scripts/v3_status.py --cases identity SE`로 구성 원본의 사례 줄을 봅니다.
   - 이미 다른 항목에서 쓴 사고는 '※ 사용 중'으로 표시됩니다.
   - 원본 문구는 `identity/output/통합_신원보안위협_매트릭스_v2.xlsx` '통합 매트릭스' 시트의 '요약설명'·'참조'·'탐지·대응 포인트'에서 봅니다.
3. **빈 필드 작성**: summary · description · scenario · cases · controls를 채웁니다. 형식은 4장, 기존 예시는 `data/identity/AU.yaml`·`data/supplychain/*.yaml`입니다.
4. **검증**: `python3 integrated/scripts/common.py`로 해당 도메인의 오류·경고 0을 확인한 뒤 커밋합니다.

참고:

- 재구성안의 대표 사례 후보는 Lv0 안에서 겹치지 않게 미리 배치한 것입니다. 바꾸면 반복 경고가 날 수 있습니다.
- ID-PE-03은 원본이 '공개 사고 미확인'입니다. 사례 줄을 `- 공개 사고 미확인 — 사유` 형식으로 씁니다.
- 원본 사례명의 '크리덴셜 스터핑'은 '자격증명 스터핑'으로 씁니다. 검증기가 원본 쪽을 같은 용어로 바꿔 대조합니다.

### 2.2 물리·인적 문안 27개 — `integrated/data/physical/<도메인>.yaml`

도메인 순서: RC → PA → SV → HU → IN → EX → IM. 절차는 2.1과 같습니다.

- 대표 사례는 재구성안에 배치돼 있지 않습니다. `--cases`로 고르되, 아래 기준을 따릅니다.
  - **국내·최근 사고를 우선**합니다(결정 D7).
  - **같은 사고(PHI-…)를 두 항목에 쓰지 않습니다**. 불가피하면 `common.CASE_REUSE_ALLOWED`에 허용 항목과 사유를 등록합니다.
- 사례 유형 `[정부 경보]`·`[위협인텔]`은 쓸 수 있지만, 실제 사고로 세지 않습니다.

### 2.3 빌드·검증 (4단계)

```bash
python3 integrated/scripts/build_integrated_matrix.py            # 내부본 + CSV + 요약 목록(v3)
python3 integrated/scripts/build_integrated_matrix.py --release  # 고객 배포본
```

- **회귀**: v2 CSV(`output/통합_요약매트릭스_v2.csv`)와 비교합니다.
  - AI·클라우드·OT 163행은 '연계 위협' 열 외에 차이가 없어야 합니다.
  - 임시 문안 시험에서는 '연계 위협' 열만 75행이 바뀌었습니다.
- **연계 참조 경고**: 빌드 출력의 '원본 연계 중 요약 ID로 바로 옮길 수 없는 참조'는 v2부터 있던 OT 3건뿐이어야 합니다.
- **합집합 보정 5건**: v2 작업방향 11.2처럼 같은 위협인지 검토해 유지·조정 사유를 기록합니다.
  - 대상: SC-SR-01 · ID-DI-01 · ID-TS-02 · PH-PA-02 · PH-SV-04
  - 조정이 필요하면 해당 항목에 `severity_override`와 근거를 넣습니다.
- **분포 확인**: 개요의 Top 10·단계 위협 기준, 공급망 포화(매우 높음 28/33 예상), Lv0별 위험도 분포를 확인합니다.

## 4. 문안 형식 (검증기 규칙 요약 — 상세는 `docs/작성기준.md` 3·4장)

| 필드 | 규칙 |
|---|---|
| `name` | 명사구, 30자 이내(경고) |
| `summary` | `- ` 없는 한 줄, 50자 이내(오류). '수단 + 대상 + 결과' 명사형 |
| `description` | `- `로 시작하는 2줄. 1줄은 '~위협'으로 끝남(오류), 2줄은 영향·탐지 곤란 사유. 줄당 130자(경고) |

| `cases` | 1~2줄 `- [유형] 사례명(시점): 요지`. `사례명(시점)`과 유형이 구성 원본 참조 줄과 일치해야 함(오류). 근거 수준이 '실제 사고 확인'이면 `[실제 사고]` 1건 이상(경고). 같은 Lv0 안 같은 사고 반복 금지(경고) |

| 신원 | 신원 유형(인력·특권·NHI·고객)과 ID 환경(AD·클라우드 IdP·SaaS)이 드러나게 |
| 물리 | 대응 방안에 드론 무력화·전파 교란 권고 금지, 보호 특성(출신·종교·인종·성별) 금지(오류) |

## 6. 알려진 주의점

- **빌드 시점**: 신원·물리 문안을 모두 쓰기 전에는 빌드가 '재구성 매핑 행 수' 확인에서 멈춥니다(의도된 동작). 그 전까지는 `common.py`와 `v3_status.py`로 검증합니다.
- **연계 위협 수**: 원본 연계 열을 전부 자동 변환하므로 일부 신원·공급망 항목은 연계 9~10개입니다. 계획 당시에는 항목당 2~3개로 제한하려 했으나 추적성을 위해 전부 싣기로 확정했습니다(작업방향 5.3). 보고서에서 줄이려면 빌드에 표시 상한을 두는 방식으로 처리합니다.
- **공급망 위험도 포화**: 매우 높음 28/33은 원본 기준(D6)에 따른 결과입니다. 공급망 안 비교는 실제 사고 수·최근 사고로 합니다.
