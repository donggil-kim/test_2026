# 통합 사고사례 목록 검증 — 검증자 지침

작업 방향: `integrated/docs/v4_사고사례_검증_작업방향.md` (5장 판정 기준이 이 지침의 근거)

## 파일

| 경로 | 내용 |
|---|---|
| `incident_verification.csv` | 원장 913행 — 키는 `원장 키`(원본 사례 ID). 검증자는 **직접 고치지 않음** |
| `inputs/<배치>.csv` | 배치 입력(25행 안팎) — 행의 기존 값(사례명·시점·요약·출처·인용 문안 등) |
| `batches/<배치>.csv` | **검증자가 쓰는 결과** — `원장 키` + 판정 열만. `python3 integrated/scripts/verify_incidents.py merge`로 원장에 병합 |

## 도구

- 원문 열람: `python3 integrated/scripts/fetch_page.py URL [--grep 키워드 ...]` — 제목·게시일 후보·본문(또는 키워드 문장). 웹페치 도구는 이 환경에서 DNS 실패하므로 쓰지 않음.
- 검색: WebSearch. **검색 결과의 요약문은 단서일 뿐 근거가 아님** — 반드시 링크를 `fetch_page.py`로 열어 원문 문장으로 판정.
  - 예: 쿠팡 건 검색 요약은 "정부 분석상 비인가 조회 약 5개월"이라 했지만, 원문(ZDNet, 정부 조사 결과)은 대량 유출 2025-04-14~11-08이고 5개월은 삭제된 로그 기간이었음.
- Wiz 집계 행(`출처` = Wiz): `https://threats.wiz.io/all-incidents/<사례명 소문자-하이픈>` 페이지에 Pub. date·References(원 출처 URL)가 있음. 슬러그가 안 맞으면 `site:threats.wiz.io 사례명` 검색.
- ramimac 집계 행: `https://raw.githubusercontent.com/ramimac/aws-customer-security-incidents/main/README.md` (사고 표 + 벤더 사례 표, 각 행에 링크).
- 일부 사이트(cisa.gov · sec.gov)는 403 — 검색 결과의 다른 1·2차 출처로 대체하고 `E 메모`에 적음.

## 행마다 할 일

1. `요약`·`사례명`에서 확인할 주장(날짜·수치·조직·행위자·CVE·피해)을 뽑는다.
2. 출처 열의 URL이 있으면 열어 제목·게시일·주장 문장을 확인한다(E축 ②존재 ③지지).
3. 사건명·조직·행위자 등 고유어로 독립 출처를 검색해 연다(요약 문장을 그대로 검색어로 쓰지 않음). 2025~2026 사건과 P0는 **독립 출처 2개 또는 1차 출처 1개**.
4. 판정 열을 채운다. `인용 문안`(대표 사례 줄)도 확정한 사실과 대조해 G축을 채운다.

## 판정 열 (값은 아래 중에서)

| 열 | 값 / 쓰는 법 |
|---|---|
| A 존재 | 확인 · 부분 확인 · 미확인 · 해당 없음 |
| B 시점 | 발생월 일치 · 공개월 일치 · 둘 다 일치 · 둘 다 아님 · 불명 · 해당 없음 (월 단위는 월이 같으면 일치, 일 단위는 ±3일) |
| 발생월 / 공개월 | `YYYY-MM`(알면 `YYYY-MM-DD`). 발생 = 최초 침해·공격 개시, 공개 = 최초 공개 보도·공지 |
| C 핵심 내용 | 일치 · 부분 일치 · 불일치 · 해당 없음 |
| C 차이 | 다른 주장만: `목록 값 → 확인 값 (근거)` 형식. 출처끼리 다르면 `출처 차이: A 값 / B 값` |
| D 사례 구분 | 적정 · 재분류 제안 (`D 제안`에 제안 구분과 이유) |
| E 출처 | 정합 · 보강 필요 · 오류 · 열람 불가 (`E 메모`: 열어 본 결과, 집계기관 행은 원 출처 URL) |
| F 묶음 | 정당 · 분리 필요 · 해당 없음 (원본 사례 ID가 둘 이상인 행만) |
| G 문안 | 일치 · 수정 필요 · 해당 없음 (`G 메모`: 고칠 문구) |
| AI 활용 | 확인 · 추정 · 없음 (공격에 AI를 썼는지 — 공식 발표·벤더 분석이면 확인, 언론 제기면 추정) |
| 종합 판정 | 통과 · 경미 수정 · 수정 필요 · 확인 불가 · 구조적 검증 불가 |
| 제안 정정 | 고칠 필드와 값: `필드: 현재 → 제안` (여러 개는 ` / `) |
| 근거 URL | 실제로 열어 확인한 URL만, ` \| `로 구분 (최대 3개, 1차 출처 우선) |
| 근거 등급 | 1차 · 2차 · 3차 (가장 높은 것) |
| 검색일 · 검증자 | `2026-10-12` · 배치명 |

종합 판정 기준:

- **통과**: A 확인 · B 발생월 또는 공개월 일치 · C 일치 · E 정합/열람 불가 · G 일치
- **경미 수정**: 존재 확인, 근사 표현·수치 출처 차이·출처 보강 필요 등 사실을 바꾸지 않는 수정
- **수정 필요**: B 둘 다 아님, 핵심 사실 오류(행위자·규모·기간·원인), 사례 구분 오류, 출처가 주장과 무관, G 수정 필요
- **확인 불가**: 서로 다른 검색어 3회 이상 + 집계기관 등재 확인 뒤에도 독립 출처 없음 (허위 확정이 아님)
- **구조적 검증 불가**: 익명 사례연구(사례명이 일반 문구)·ATT&CK 그룹처럼 사건 단위가 아닌 행 — 보고서·ID 실재만 확인하고 그 결과를 `비고`에

## 금지

- 원장·원본 DB·`data/<Lv0>/*.yaml`·빌드 산출물을 고치지 않음. 결과는 `batches/<배치>.csv`에만.
- 추정을 확인처럼 쓰지 않음. 열지 못한 URL을 근거 URL에 넣지 않음.
- git 커밋·푸시 하지 않음.
