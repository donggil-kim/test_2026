# 통합 보안위협 매트릭스 v4

여섯 원본 매트릭스를 각 원본 데이터 그대로 활용해, 컨설팅 보고서용 **요약 위협 매트릭스 하나**로 통합했습니다.

- **통합 AI 보안위협 매트릭스 v3.2**(LITE, Lv3 124개)
- **통합 클라우드 보안위협 매트릭스 v5**(Lv3 154행, 고유 기법 126개)
- **통합 OT/ICS/IoT 보안위협 매트릭스 v5**(Lv3 141행, 고유 기법·항목 118개)
- **통합 소프트웨어 공급망 보안위협 매트릭스 v2**(세부위협 60개)
- **통합 신원·계정 보안위협 매트릭스 v2**(세부위협 65개)
- **물리·인적 보안위협 매트릭스 v2**(세부위협 45개)

v4는 v3(6개 Lv0, 258개)의 **Lv0 간 중복을 통합**하고 **통합 사고사례 목록**을 추가한 판입니다. v3·v2·v1 산출물은 이력으로 보존합니다.

- **중복 통합**: Lv0를 넘어 사실상 같은 위협 21건을 원본 경계 규칙상 주관 Lv0 항목에 흡수(258 → 237개), 관점이 다른 겹침 138개는 **중복 그룹 38개**로 표시
  - 흡수한 항목의 위험도는 주관 Lv0 원본 기준이며, 흡수한 다른 Lv0 원본은 참고 평가로만 표기합니다(결정 V3).
  - 고유 위협 수(추정) **137개** = 그룹 밖 99 + 그룹 38
- **통합 사고사례 목록**: 요약 위협이 참조하는 사고·사례 **913건**(실제 사고 834건)을 여섯 원본 사고 DB에서 모아, 여러 DB에 실린 같은 사고(77건)는 한 행으로 묶음
- 결정 사항·판정 원칙·결과는 [`docs/v4_중복통합_작업방향.md`](docs/v4_중복통합_작업방향.md), 검토표는 `output/통합_중복검토_v4.md`

구조

- **Lv0 구분**: AI / 클라우드 / OT(ICS·IoT 포함) / 공급망(소프트웨어 공급망) / 신원(계정·IdP·비인간 신원·고객 계정) / 물리·인적(물리 침입·감시·포섭·내부자) 보안위협
- **Lv1 도메인**: 원본 분류를 그대로 사용
  - AI: 원본 10개 도메인(D01~D10)
  - 클라우드: 원본 ATT&CK 14개 전술(RD~IM)
  - OT: 원본 ATT&CK for ICS 12개 전술 + 자원 개발, 13개(RD~IM)
  - 공급망: 원본 8개 단계(DE~IM) · 신원: 원본 10개 공격면(AU~IM) · 물리·인적: 원본 7개 공격면(RC~IM)
- **Lv3 세부 위협**: 원본 Lv3의 맥락·내용을 분석해 재구성·재작성 — **합계 237개**
  - AI 124 → 60개, 클라우드 154행(126기법) → 38개, OT 141행(118기법·항목) → 50개
  - 공급망 60 → 30개, 신원 65 → 32개, 물리·인적 45 → 27개
  - 원본 Lv2는 요약표에서 생략하고 원본 상세 시트로 추적
- **Lv3 옆 별도 열**: 핵심 요약 · 위협 설명 · 공격 시나리오 · 대표 사례 · 위험 평가(우선순위 포함) · 대응 방안 · 공격 단계 · 관련 기준 · 연계 위협 · 중복 그룹 · Lv0 간 통합 흡수(v3 ID) · 원본 Lv3 ID
- **보고서 활용**: 본문에는 `보고서용 간략 매트릭스` 시트(핵심 요약·위험도·우선순위·대표 사례 1건·핵심 대응 1줄·중복 그룹), 부록에는 `통합 요약 매트릭스`와 `통합 사고사례 목록`
  - 237행이라 보고서 본문은 Lv0별 Top 10과 간략 매트릭스 필터 사용을 권장합니다. Lv0를 가로질러 위협 수를 말할 때는 고유 위협 수(추정)를 쓰세요.

**v4 Lv0 간 통합·중복 그룹·동일 사고**

```yaml
# data/<Lv0>/<도메인>.yaml — 흡수한 항목에만
  absorbs:                            # 다른 Lv0의 v3 위협을 흡수 (같은 Lv0 통합은 members로)
    - id: CL-IA-03                    # 폐기한 v3 위협 ID (재사용하지 않음)
      name: 피싱 기반 클라우드 계정 탈취   # v3 명칭
      members: [T1566, T1566.002]     # 그 Lv0 원본 키 — 전수 배정·역참조·참고 평가에만 쓰고 위험 산정에는 쓰지 않음(결정 V3)
      reason: …                       # 흡수 사유 → 부록-Lv0 간 통합 · 재구성 매핑 '통합 근거'

# data/dup_groups.yaml — 관점이 달라 유지한 겹침
- id: G03
  name: 피싱과 계정 탈취
  lead: ID-SE-01                      # 대표 위협 (items에 포함)
  items: [ID-SE-01, OT-IA-04, CL-LM-02, SC-SC-03]   # 한 위협은 한 그룹에만
  basis: …                            # 통합하지 않고 유지한 근거

# data/incident_aliases.yaml — 여러 사고 DB에 실린 같은 사고 (첫 ID가 목록의 대표 기록)
- {ids: [SCI-052, IDI-027, CL/INC-0062], note: SolarWinds …}   # 클라우드 DB는 CL/, OT DB는 OT/ 접두사
```

- 흡수 원본 참조의 사례도 흡수한 항목의 대표 사례로 쓸 수 있습니다(빌드가 출처 대조).
- 원본 연계 열·문안 `links`의 폐기 ID는 빌드가 흡수 ID로 바꿉니다. 문안에는 현행 ID를 적으세요.

- OT 전술 반복 기법은 요약 항목의 주 전술 행 값으로 평가합니다.
- 공급망·신원·물리 문안 골격은 `python3 integrated/scripts/v3_status.py --skeleton <kind> <도메인>`, 대표 사례 후보는 `--cases <kind> <도메인>`으로 봅니다.
- 세부 규칙(OT·공급망·신원·물리 보충 포함)은 [`docs/작성기준.md`](docs/작성기준.md)를 참조하세요.
