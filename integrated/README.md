# 통합 AI·클라우드·OT 보안위협 매트릭스 v2

세 원본 매트릭스를 각 원본 데이터 그대로 활용해, 컨설팅 보고서용 **요약 위협 매트릭스 하나**로 통합했습니다.

- **통합 AI 보안위협 매트릭스 v3.2**(LITE, Lv3 124개)
- **통합 클라우드 보안위협 매트릭스 v5**(Lv3 154행, 고유 기법 126개)
- **통합 OT/ICS/IoT 보안위협 매트릭스 v5**(Lv3 141행, 고유 기법·항목 118개)

v1(AI·클라우드 113개)에 OT를 세 번째 Lv0로 더한 판입니다.

- **Lv0 구분**: AI 보안위협 / 클라우드 보안위협 / OT 보안위협(ICS·IoT 포함)
- **Lv1 도메인**: 원본 분류를 그대로 사용
  - AI: 원본 10개 도메인(D01~D10)
  - 클라우드: 원본 ATT&CK 14개 전술(RD~IM)
  - OT: 원본 ATT&CK for ICS 12개 전술 + 자원 개발, 13개(RD~IM)
- **Lv3 세부 위협**: 원본 Lv3의 맥락·내용을 분석해 재구성·재작성 — **합계 163개**
  - AI 124 → 61개, 클라우드 154행(126기법) → 52개, OT 141행(118기법·항목) → 50개
  - 원본 Lv2는 요약표에서 생략하고 원본 상세 시트로 추적
- **Lv3 옆 별도 열**: 핵심 요약 · 위협 설명 · 공격 시나리오 · 대표 사례 · 위험 평가(우선순위 포함) · 대응 방안 · 공격 단계 · 관련 기준 · 연계 위협 · 원본 Lv3 ID
- **보고서 활용**: 본문에는 `보고서용 간략 매트릭스` 시트(핵심 요약·위험도·우선순위·대표 사례 1건·핵심 대응 1줄), 부록에는 `통합 요약 매트릭스`

## 빌드·검증

```bash
pip install openpyxl pyyaml
python3 integrated/scripts/common.py                  # 요약 문안 검증만 (오류·경고 출력)
python3 integrated/scripts/build_integrated_matrix.py           # 내부본: 검증 → 워크북·CSV·목록 생성 → 저장본 재검증
python3 integrated/scripts/build_integrated_matrix.py --release # 고객 배포본(CSA 열 이슈 ID만)
```

검증 항목:

- **전수 배정**: 원본 AI Lv3 124개·클라우드 고유 기법 126개·OT 고유 기법·항목 118개가 요약 항목에 빠짐없이, 한 번씩만 배정되었는지
- **문안 형식**
  - 핵심 요약: 한 줄 50자 이내
  - 위협 설명: 2줄, 1줄은 '~위협'으로 종결
  - 시나리오: '→' 흐름 1~2줄 · 사례: 1~2줄 · 대응 방안: 2~3줄
  - 줄당 길이 상한, 금지 용어(인증정보·크리덴셜 등)
- **사례 출처 대조**: 대표 사례의 '사례명(시점)'과 유형 태그가 구성 원본의 참조 열에 실제로 있는지 (새 사실 추가 방지)
  - OT는 `[위협인텔]`·`[EMB3D]` 유형을 추가로 허용
- **사례 분산(OT)**: 같은 사고를 여러 항목의 대표 사례로 쓰면 경고
  - 원본 참조 줄의 사고 ID(INC-…) 기준이라, 이름이 다른 같은 사고도 잡음
  - 불가피한 반복은 `common.CASE_REUSE_ALLOWED`에 허용 항목·사유를 등록 (`docs/작성기준.md` 4장)
- **근거 정합성**: 근거 수준이 '실제 사고 확인'인 항목에 [실제 사고] 사례가 있는지, 연계 위협 ID가 존재하는지
- **원본 재현**: AI·클라우드·OT 실제 사고 수와 클라우드·OT 최근 사고 수를 사례 ID·기준일로 다시 세어 원본 값과 일치하는지 확인
- **저장본 재검증**
  - 시트 10개, 행 수(요약 163 / AI 상세 124 / 클라우드 상세 154 / OT 상세 141 / 재구성 매핑 419)
  - 역참조 ID 유효성, 위험도·근거 수준 값, Lv0별 우선순위 1..N, 요약 항목마다 위험 대표 원본 표시
  - 배포본 CSA 열의 ID 표기, 수식 셀 없음

## 요약 문안 수정

요약 문안은 `data/` 아래 YAML만 고치고 다시 빌드합니다. 항목 형식:

```yaml
- id: OT-LM-02                      # AI-<도메인번호>-<순번> / CL-<전술>-<순번> / OT-<전술>-<순번>
  name: 유효 계정 악용               # 세부 위협(Lv3), 30자 이내
  summary: 탈취·퇴사자·새로 만든 유효 계정으로 VPN·원격 서비스·제어 장치에 로그인   # 핵심 요약, 한 줄 50자 이내
  members: [T0859]                  # 구성 원본: AI는 UT Lv3 ID, 클라우드는 ATT&CK ID(또는 AZT…), OT는 ATT&CK·EMB3D ID
  basis: 단독 유지 — …              # 통합 근거 (단독이면 '단독 유지 — 사유')
  links: [CL-IA-07]                 # 선택: 교차 연계 (양방향으로 자동 표기)
  description: |-
    - … 위협
    - …
  scenario: |-
    - … → … → …
  cases: |-
    - [실제 사고] 사례명(2021-01): 요지
  controls: |-
    - …
    - …
```

위험 평가(발생가능성·심각도·위험도·근거 수준·실제 사고 수·최근 사고·우선순위)는 구성 원본에서 자동 재산정되므로 문안에 적지 않습니다.

- OT 전술 반복 기법은 요약 항목의 주 전술 행 값으로 평가합니다.
- 세부 규칙(OT 보충 포함)은 [`docs/작성기준.md`](docs/작성기준.md)를 참조하세요.
