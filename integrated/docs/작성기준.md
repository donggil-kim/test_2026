# 통합 보안위협 매트릭스 — 작성·평가 기준

요약 Lv3 재구성, 위험 재산정, 문안 작성에 적용한 기준입니다. 원본 개별 항목의 산정 규칙은 각 원본 워크북의
평가 기준 시트(AI v3.2 `도메인·평가기준`, 클라우드 v5 `평가 기준`)를 따릅니다.

## 1. 재구성 원칙

| 구분 | 기준 |
|---|---|
| 단위 | 원본 Lv3(AI 124개, 클라우드 고유 기법 126개·154행)를 묶어 요약 Lv3로 재구성 (AI 61개, 클라우드 52개) |
| 통합 | ① 같은 공격 흐름의 연속 단계(예: 토큰 탈취 → 탈취 토큰 재사용) ② 대상만 다른 같은 기법(예: 비밀번호 추측·스프레이·스터핑) ③ 같은 통제로 막히는 위협 |
| 분리 유지 | 피해 규모·근거 밀도·통제가 뚜렷이 다르면 메커니즘이 비슷해도 분리 (예: 협업 저장소 / 코드 저장소 / 고객·업무 DB 수집) |
| 단독 유지 | 묶을 대상이 없는 고유 위협. `basis`에 `단독 유지 — 사유`로 기록 |
| 근거 기록 | 모든 항목에 `basis`(통합 근거) 기록 → 워크북 `부록-재구성 매핑`의 '통합 근거' 열 |

## 2. 위험 평가 (요약 Lv3 재산정)

요약 항목의 위험 평가는 문안에 적지 않고 **구성 원본에서 자동 재산정**합니다(`common.evaluate_ai/evaluate_cloud`).

| 항목 | 규칙 |
|---|---|
| 위험도 | **구성 원본별 위험도(발생가능성 × 심각도)의 최댓값**. 발생가능성과 심각도를 서로 다른 원본에서 가져와 조합하지 않습니다(교차 결합 금지). 3×3 표는 아래와 같으며 원본 두 매트릭스와 동일 |
| 발생가능성 보정 | 구성 원본의 실제 사고 합집합이 2건 이상이면, 사고가 1건 이상 확인된 원본만 발생가능성을 '상'으로 보정 |
| 발생가능성·심각도 | 위험도 최댓값을 낸 원본(**대표 원본**)의 값을 표시. 동률이면 실제 사고 수 → 심각도 → 발생가능성 순으로 선택. 대표 원본은 `부록-재구성 매핑`의 '위험 대표' 열에 ● 표시 (필요 시 `severity_override`로 근거와 함께 조정 — v1에서는 사용하지 않음) |
| 실제 사고 수 | **AI**: 구성 원본의 ATLAS Incident 유형 사례 ID(중복 제거) + OWASP 인용 사고 수. OWASP 인용 사고는 ID 없이 건수만 있으므로, 원본별 건수 합에서 참조에 같은 사례명(시점)으로 실린 중복분을 뺍니다<br>**클라우드**: 구성 원본의 사고 DB ID(중복 제거) — 집계 대상 유형(사고·캠페인·사례연구(익명)·규제공시(8-K)·위협인텔 보고서, 집계 포함=Y) |
| 최근 사고(2025~) | 실제 사고 중 2025년 이후 사고 수. 클라우드: 사고 DB 기준일(원본 v5 '최근 사고' 열과 일치 확인). AI: ATLAS 사례 일자 + 참조에 시점이 적힌 OWASP 인용 사고(시점이 없는 인용 사고는 제외) |
| 우선순위 | 같은 Lv0 안에서 위험도 → 실제 사고 수 → 최근 사고(2025~) → 위협 ID 순으로 매긴 순위(1 = 최우선). 개요에 Lv0별 Top 10 |
| 근거 수준 | 구성 원본 중 가장 강한 수준: 실제 사고 확인 > 실사용 기법 포함 > 실증·공개 취약점 > 이론·시나리오 |

| 발생가능성 \ 심각도 | 상 | 중 | 하 |
|---|---|---|---|
| 상 | 매우 높음 | 높음 | 보통 |
| 중 | 높음 | 보통 | 낮음 |
| 하 | 보통 | 낮음 | 낮음 |

**Lv0 간 비교 유의** — 클라우드는 사고 DB(680건) 기반이라 실제 사고 근거가 AI(ATLAS 사례·OWASP 인용)보다 촘촘합니다.
위험도·사고 수·우선순위는 같은 Lv0 안에서 비교하고, AI와 클라우드의 등급을 직접 비교하지 않습니다.

**신규 공격면 유의** — 발생가능성은 확인된 실제 사고 기준이라, 공개 취약점은 많으나 사고 보고가 적은 신규 공격면
(예: AI-02-03 간접 프롬프트 인젝션 — 공개 취약점 4건, 확인된 사고 0건 → '높음')은 과소평가될 수 있습니다.

**규칙 변경 이력 (v1 검토 반영)** — 초기 v1은 발생가능성(합집합 사고 기준)과 심각도(구성 원본 최댓값)를 따로 구해 조합해,
어느 구성 원본보다 높은 등급이 나오는 항목이 있었습니다. 원본별 최댓값 규칙으로 바꿔 5건이 한 단계 내려갔습니다:
AI-02-05·AI-03-02·AI-03-07 높음→보통, AI-09-01 보통→낮음, CL-DI-02 매우 높음→높음.
사고 합집합 근거로 올라간 3건(AI-01-09·AI-04-03·AI-05-03)은 유지됩니다. AI-06-02 실제 사고 수는 OWASP 인용 중복(Replit) 제거로 5→4건.

## 3. 문안 작성 기준

| 열 | 형식 | 길이(줄당) |
|---|---|---|
| 세부 위협(Lv3) | 명사구. 묶은 범위가 드러나게 (예: `인증 통제 변조(MFA·조건부 액세스·장치 등록)`) | 30자 |
| 핵심 요약 | 한 줄. `수단 + 대상 + 결과`를 명사형으로 (예: `유출·탈취한 키·계정으로 콘솔·API에 정상 로그인`). 보고서 본문·슬라이드용 | 50자 |
| 위협 설명 | `- ` 2줄. **1줄**: 공격 방법 + 대상 + 결과, `~위협`으로 종결. **2줄**: 영향·발생 조건·탐지 곤란 사유, 명사형 종결(~됨·~어려움·~이어짐 등) | 130자 |
| 공격 시나리오 | `- A → B → C` 1~2줄. 구성 원본의 참조·사례에 있는 경로만 사용 | 175자 |
| 대표 사례 | `- [유형] 사례명(시점): 요지` 1~2줄 (4장) | 130자 |
| 대응 방안 | `- ` 2~3줄 명사형. 예방(권한·구성) → 보호·차단 → 탐지 순 | 80자 |

- 원본에 없는 새 사실을 추가하지 않습니다. 수치·사례·제품명은 구성 원본의 요약설명·참조에서만 가져옵니다.
- 용어 통일: **자격증명**(인증정보·크리덴셜 사용 금지 — 검증기가 차단), **반출**(빼내는 행위) / **유출**(새어 나간 결과).

## 4. 대표 사례 기준

| 유형 | 정의 |
|---|---|
| [실제 사고] | 공개 보도·공시·위협 인텔로 확인된 실제 침해·악용 |
| [공개 취약점] | CVE·공개 보안 권고로 확인된 취약점 |
| [실증] | 연구·레드팀·벤더가 실제 제품에서 재현한 공격 (원본 표기 `[실증·연구]` 포함) |
| [ATT&CK 사례] | MITRE ATT&CK에 기록된 그룹·소프트웨어·캠페인의 사용 사례 |
| [시나리오] | OWASP 등 기준 문서의 가상 시나리오 |
| 공개 사고 미확인 — 사유 | 구성 원본 모두 사례가 없을 때만 사용 (원본 참조에 '공개 사고 미확인'이 있어야 허용) |

- **출처 대조**: 사례의 `사례명(시점)`과 유형이 구성 원본 참조 열에 그대로 있어야 합니다(검증기 자동 확인).
- **우선순위**: 실제 사고 → 공개 취약점·실증 → ATT&CK 사례 → 시나리오. 근거 수준이 '실제 사고 확인'이면 [실제 사고]를 1건 이상 넣습니다.
- **분산 배치**: 같은 사고가 여러 행에 반복되지 않게 배치합니다. 구성 원본의 유일한 실제 사고라 반복이 불가피한 경우만 허용
  (예: APT29 M365 골든 SAML — CL-CA-04·CL-PV-02, OpenAI 평가용 자율 에이전트 — 사고의 서로 다른 단계를 AI 4개 항목에서 사용).

## 5. 교차 매핑·추적 열

| 열 | 산정 |
|---|---|
| 공격 단계 | AI: 구성 원본 '주 공격 단계'(ATLAS 전술) 합집합을 클라우드(ATT&CK v19.2 국문) 용어로 통일 — 초기 접근→초기 침투, 내부 확산→횡적 이동, 유출→반출 (방어 회피처럼 1:1 대응 용어가 없는 단계는 원문 유지). 클라우드: 주 전술 + `(연관: 원본 중복·이동 전 전술)`. 단계 구분은 쉼표(명령·제어처럼 이름에 가운뎃점이 있어서). 원본 상세 시트는 원문 그대로 |
| 관련 기준 | AI: `OWASP` 주 매핑 + `ATLAS` 기법(상위 ID). 클라우드: `ATT&CK` ID(상위기법별 축약, 예 `T1552, T1552.001·.008`) + `CSA` Top Threats 2026 이슈 ID. **CSA·CCM 문서 내용은 싣지 않고 연계 ID만 표기** |
| 연계 위협 | AI↔클라우드 연계. 클라우드 원본 'AI 매트릭스 연계(UT)' 열(7개 기법) + 문안의 `links`를 양방향으로 표기 |
| 원본 Lv3 ID | AI: UT Lv3 ID. 클라우드: v5 CTC-ID(전술 중복 행 모두) |

## 7. 용어

| 용어 | 뜻 |
|---|---|
| 자격증명 | credential — 비밀번호·액세스 키·토큰·인증서 등 인증 수단 전체 |
