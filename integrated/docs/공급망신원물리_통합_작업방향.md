## 1. 한눈에 보기

- **목표**: 세 상세 매트릭스(공급망 60 · 신원 65 · 물리 45 = 170개)를 v2와 같은 방식으로 요약 Lv3 **95개**로 재구성해
  통합본에 Lv0 3개를 추가 → **v3 = AI 61 + 클라우드 52 + OT 50 + 공급망 33 + 신원 35 + 물리·인적 27 = 258개** (1단계 확정, 계획 당시 목표 약 89개)
- **방향**: 세 원본은 **같은 빌드 틀**(자체 분류 체계 `taxonomy.yaml` → 도메인 · 위협분류(Lv2) · 세부위협(Lv3), 사고 DB `incidents.yaml`,
  관점 문구 `text/*.yaml`, 같은 위험 산정 규칙)로 만들어졌습니다. 그래서 **공용 로더 1개**로 세 원본을 읽고,
  v2의 위험 재산정 · 재구성 매핑 · 원본 상세 시트 경로를 그대로 씁니다.
  - 클라우드·OT(ATT&CK 전술 뼈대)와 달리 Lv1이 **자체 도메인**이고 원본에 이미 Lv2(위협분류)가 있음 → 재구성의 출발점으로 활용
  - 새로 다룰 요소: Lv0 간 중복(특히 신원↔클라우드), 공급망 위험도 포화, 물리 매트릭스의 방어 자료 작성 제약, 추가 사례 유형·라이선스
- **순서**: ⓪ 기준선 정리 → ① 재구성 설계 확정 → ② 코드를 Lv0 6개 구조로 확장 → ③ 문안 작성(공급망 → 신원 → 물리, 각 파일럿 후 전체)
  → ④ 빌드·검증 → ⑤ 문서화 → ⑥ 검토 반영

## 5. 재구성 기준과 규모(검토용)

### 5.1 원칙 (v2 `작성기준.md` 1장 그대로)

## 8. 문안 작성 보충 기준

- 형식·길이는 v2 `작성기준.md` 3장 그대로. 수치·사례는 구성 원본의 문구·사고 DB 요약에만 근거
- **공급망**: 핵심 요약에 공급망 단계(개발·빌드·게시·소비)가 드러나게. 대응은 원본 S2C2F·SSDF 통제를 요약
- **신원**: 신원 유형(인력·특권·NHI·고객)과 ID 환경(AD·클라우드 IdP·SaaS)이 드러나게. 용어는 '자격증명' 통일(원본의 '크리덴셜 스터핑'은 '자격증명 스터핑')
- **물리**: 방어 자료 규칙(D9). 수법은 '징후' 수준, 대응은 예방 → 차단 → 탐지의 합법적 조치. 임직원 모니터링은 개인정보보호법·노사 협의 범위 명시
- **대표 사례 분산**: 같은 사고가 Lv0 안에서 반복되지 않게(v2 OT 방식). 다른 Lv0와의 반복은 허용하되 같은 사고면 서로 다른 단계를 씀(1단계에서 Lv0 간 공통 사고 목록 산출)

## 9. 유의사항
