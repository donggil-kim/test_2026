# 고도화·레거시 우회 엔터프라이즈 침해 보안위협 매트릭스 — 방법론

> 범위: ATT&CK Enterprise에서 ① 고도화됐고 ② 최근 실제 사례가 많으며 ③ 레거시 보안체계(시그니처 AV·경계 방화벽·레거시 SIEM)로 막기 어려운 기법.
> 상태: **③ v2(관점 문구·공격 체인 시나리오)·④ 통합 v5 뷰 완료(2026-10-26)** — 세부위협 51개(문구 51), 사고 DB 28건(v3), 시나리오 8개, 검증 오류·경고 0(`--strict`).

## 0. 가드레일(D11)

- **방어 자료**: 모든 서술은 위험·탐지·대응 중심. 공세 제작법·악용 절차는 적지 않고 역량의 존재·영향·탐지·완화 단서까지만 식별 수준으로 씁니다(검증기가 금지 표현 차단).
- **공개 저장소**: 유료 표준 원문·비공개 자료·개인정보 미수록, ID·명칭만 연계.
- **사실 근거**: 공개 출처에 있는 것만. 벤더·2차 수치는 참고치로만 쓰고 사고 DB에는 1차 확인 사례만. 발생가능성 '상'은 실제 사고 2건 이상.
- **모델 식별자 금지**: 저장소 아티팩트에 제품명·버전 같은 모델 식별자를 넣지 않습니다.

## 1. 렌즈 매트릭스 — 다른 매트릭스와 다른 점

기존 6개 매트릭스는 자산·공격면이 축입니다. 이 매트릭스는 **방어 난이도(레거시 공백)**가 축인 렌즈 매트릭스로, 자산이 무엇이든 "레거시로 막기 어렵다"로 묶습니다(작업방향 2·4장). 그래서:

1. **중복**: 기존 6개와 겹칩니다 → 재수록 대신 **통합 v4.1 요약 ID(AI·CL·OT·SC·ID·PH)로 연계만**(5장·D9).
2. **선정**: 697개 전부가 아니라 **고도화·최근빈발·레거시난제** 점수로 선별합니다(§3, D5).
3. **고유 축**: **레거시 방어 공백 유형**과 **요구 방어 수준**을 행 속성으로 둡니다(D6, §3).

## 3. 분류 체계 (D6)

- **Lv1 도메인 = ATT&CK Enterprise 전술**(침투~영향 12개: IA·EX·PE·PV·DE·CA·DI·LM·CO·C2·EF·IM). 전술 14개 중 정찰·자원 개발은 영역 1(AI)·정찰이 다뤄 제외·연계(D7).
- **Lv2 위협분류(ENT-<전술>-NN) → Lv3 세부위협(ENT-<전술>-NN.m)**.
- **고유 축**: `legacy_gap` 레거시 방어 공백 유형(시그니처 회피·파일리스·서명된 정상 도구·암호화 채널·정상 인증 위장·경계 밖 장비·커널 펌웨어·신뢰 관계) · `defense_level` 요구 방어 수준(레거시 / EDR·XDR / 행위·네트워크·아이덴티티).
- 분포(v3): 위험도 매우 높음 6·높음 15·보통 25·낮음 5 / 심각도 상 8·중 42·하 1(영향만 재판정) / 요구 방어 수준 행위·네트워크·아이덴티티 27·EDR·XDR 24.

## 4. 선정·근거·발생가능성 (D5)

- **선정(포함)**: 고도화(BYOVD·프로세스 인젝션·LOLBin·EDR 변조·파일리스·펌웨어 등) · 최근·빈발(사고 매핑 + ATT&CK 절차 사례 + KEV 악용) · 레거시 난이도(§3 공백 유형) 중 **둘 이상**. 자산 특화는 제외·연계(D7).
- **발생가능성**: 상 = 실제 사고 2건 이상, 중 = 실제 사고 1건 또는 KEV·정부 경보·위협인텔·실증·ATT&CK 주체 사례 하나 이상, 하 = 근거 없음.
- **v3 P3 공통 적용(검토 6.1)**: 상 = 실제 사고 2건 이상 **그리고 서로 다른 행위자·캠페인 2개 이상**(같은 캠페인 중복 집계 방지). 심각도는 **영향만**으로 판정(레거시 미탐지·탐지 난이도는 고유 축·우선순위). 경계 플래그(실제 사고 1건 빼면 등급 하락, 10행) 신설. **행별 심각도 재판정과 빈발 지수(ATT&CK 절차 백분위+KEV)는 영역 2 구조 개편(P1~P4, v19.2 13전술·기법 일반 서술 13건 교체)과 함께 일괄 반영 예정** — 그때까지 위험도 분포(매우높음 17·높음 12·보통 21·낮음 1)는 재판정 전 값.
- **우선순위**: 위험도 → 실제 사고 수 → **요구 방어 수준(방어 난이도)** → ATT&CK 주체 수 → ENT-ID.
- ATT&CK 주체(그룹·소프트웨어·캠페인) 절차 수(총 6,087건)를 '빈발' 신호로, CISA KEV(경계·엣지 장비 비중 연도별 14~21%)를 '엣지 0-day·빠른 n-day' 근거로 씁니다.

## 7. 빌드·검증

```bash
python3 scripts/prepare_attack.py && python3 scripts/prepare_kev.py && python3 scripts/prepare_lolbas.py && python3 scripts/prepare_refs.py
python3 scripts/validate.py --strict                         # 데이터·문구·시나리오 검증(오류·경고 0)
```

검증기(`validate.py`)는 분류 체계 필드·어휘·ID, ATT&CK·KEV(CVE 대조)·NIST·연계·참고 문헌 키, 레거시 공백·요구 방어 수준·주체·플랫폼 어휘, 사고 DB·문구(형식·사례 라벨↔집계 상태·시점·수치)·시나리오·가드레일을 기계적으로 대조합니다.

### 7.1 v1·v2 위험평가 결과

- 위험도(v3) 매우 높음 6·높음 15·보통 25·낮음 5. 심각도 영향만 재판정(엔에이블러 행 중으로)·빈발 지수(ATT&CK 절차 수 ≥100 상·≥30 중)·실제 사고 정리(24건) 반영. 상위: 사람 운영 랜섬웨어(IM-01)·이중 협박(IM-05)·대량 반출(EF-02)·MSP 신뢰(IA-05)·복구 방해(IM-02)·웜 확산(LM-04).
- 우선 위협 1~6위: 경계·엣지 0-day(IA-01)·사람 운영 랜섬웨어(IM-01)·EDR 무력화 BYOVD(DE-01.1)·원격 서비스 RDP/SMB(LM-01)·외부 원격 서비스 VPN(IA-02)·LSASS 덤프(CA-01.1).

### 7.2 관점 문구·공격 체인 시나리오(v2)

- 관점 문구 51/51: oneline·summary·■ 관점/실제 사례·■ 탐지/대응. 인용 사례 83건. 실제 사고 없는 5개 행은 '공개 사고 미확인 — 사유'+ATT&CK 주체로 근거 표기. 가드레일 D11 적용.
- 공격 체인 시나리오 8개(ESN-01~08): 엣지 0-day→LotL→확산, 사람 운영 랜섬웨어(BYOVD·복구 방해), 파일전송 0-day 갈취, 웜 확산→파괴, 비콘 C2, MSP 신뢰 관계, 지표 삭제 은닉, 커널·펌웨어 하위 계층.

### 7.3 통합 v5 뷰(④)

- `build_integrated_view.py` — 통합본 v4.1(237개)에 뷰(view) Lv0로 편입(D9). 세부위협 51개 연계가 기존 237개 중 **16개**를 닿음(교차 17건). 고유 위협 수 불변. 렌즈가 호스트·네트워크 중심이라 자산 기반 6개 매트릭스와 접점이 AI 활용 공격보다 적습니다.
